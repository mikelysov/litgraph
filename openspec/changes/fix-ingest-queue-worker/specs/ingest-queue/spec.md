# Spec Delta

## Purpose

Постановка статей в очередь индексирования через HTTP API и их разбор worker'ом:
валидный контракт запроса, дедупликация в Redis и обработка payloads обоих
форматов — так, чтобы `POST /api/ingest` работал и переживал рестарты контейнеров.

## ADDED Requirements

### Requirement: Контракт запроса на ингест

`POST /api/ingest` SHALL принимать тело с полями `id`, `title`, `abstract`,
`authors` (список строк). Поле `url` SHALL быть опциональным. Валидное тело без
`url` MUST ставить статью в очередь и возвращать статус статьи.

#### Scenario: Ингест без url
- **WHEN** клиент отправляет `POST /api/ingest` с `id`, `title`, `abstract`, `authors` и без `url`
- **THEN** ответ имеет HTTP 200 и статус статьи `queued`

#### Scenario: Валидация обязательных полей
- **WHEN** клиент отправляет тело без `id` или без `abstract`
- **THEN** ответ имеет HTTP 422 с описанием недостающего поля

### Requirement: Атомарная постановка в очередь

Постановка в очередь SHALL добавлять id статьи во множество дедупликации и
payload в список очереди. Повторная постановка статьи с уже находящимся в
очереди id MUST быть no-op. Используемый Redis-клиент MUST вызываться с
сигнатурой, совместимой с upstash-redis (позиционные аргументы).

#### Scenario: Повторный ингест той же статьи
- **WHEN** статья с id, уже присутствующим во множестве очереди, отправляется на ингест повторно
- **THEN** очередь не растёт и ответ по-прежнему успешен

#### Scenario: Ингест после фикса проходит end-to-end
- **WHEN** `POST /api/ingest` вызывается с валидным телом, а worker запущен
- **THEN** worker забирает статью из очереди, и статус статьи становится `embedded`

### Requirement: Worker понимает формат payload

Worker SHALL валидировать payload из очереди как конверт `{"paper": {...}, "attempts": N}`
и как «голый» JSON статьи. Payload, валидный в любом из форматов, MUST
обрабатываться; невалидный payload отбрасывается с предупреждением.

#### Scenario: Конверт с попытками
- **WHEN** worker извлекает payload вида `{"paper": {...}, "attempts": 2}`
- **THEN** статья обрабатывается, счётчик попыток сохраняется

#### Scenario: Голый JSON статьи
- **WHEN** worker извлекает payload в виде прямого JSON статьи
- **THEN** статья обрабатывается как при 0 попыток

### Requirement: Worker использует актуальный код

Долгоживущий worker-контейнер после обновления кода в примонтированном томе
MUST быть перезапущен прежде, чем по нему судят о поведении нового кода.
Эксплуатационная процедура внесения изменений в ingest-путь SHALL включать
рестарт worker'а.

#### Scenario: Код обновлён, worker перезапущен
- **WHEN** после изменения модулей ingest-пути выполняется рестарт контейнера worker'а
- **THEN** worker обрабатывает payloads по новой логике без ручного вмешательства
