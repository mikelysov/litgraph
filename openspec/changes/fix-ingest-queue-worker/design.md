# Design

## Context

`_redis_enqueue` вызывает `eval_fn(_ENQUEUE_LUA, keys=[...], args=[...])` — это
kwargs-стиль другого клиента (async-ветка upstash?). Установленный upstash-redis
1.4.0 имеет сигнатуру `eval(script, numkeys, *keys_and_args)`. Fallback-ветка
рядом уже делает `sadd` → `rpush` корректно. Модель `Paper` требует `url: str`,
но ни worker, ни vector store, ни graph store поле не читают — только `arxiv.py`
и `pdf.py` его записывают. Worker в docker держит модули, импортированные при
старте; код монтируется volume'ом, но процесс его не подхватывает.

## Goals / Non-Goals

**Goals:**
- `POST /api/ingest` работает end-to-end: 200 → очередь → worker → `embedded`.
- Минимум диффа; никакого нового кода там, где работает существующий.

**Non-Goals:**
- Переделка очереди на надёжный брокер, at-least-once семантика.
- Выпиливание `url` из модели (ломает `arxiv.py`/MCP без выгоды).
- Разбор латентности LM Studio (отдельная история, не воспроизвелась).

## Decisions

1. **Удалить Lua-скрипт, оставить sadd+rpush.**
   Альтернативы: (а) переписать вызов eval в позиционный стиль
   `eval(script, 2, QUEUE_SET, QUEUE_LIST, paper.id, payload)` — работает, но
   Lua ради one-shot дедупликации — лишний код (YAGNI); (б) `SET NX` + `RPUSH` —
   ещё один способ, без выигрыша. Окно гонки между SADD и RPUSH существует и
   сейчас в fallback-ветке; для локального single-worker инстанса — приемлемый
   потолок. Пони потолка: транзакция `MULTI/EXEC` или pipeline, когда появится
   второй worker.

2. **`Paper.url` → `url: str = ""` (не удалять).**
   Альтернатива — удалить поле и почистить все конструкторы: больше диффа,
   риск задеть MCP-путь. Дефолт пустой строки минимально меняет контракт.
   Пони потолка: если URL понадобится для дедупликации/показа источника —
   тогда решать, валидировать ли формат.

3. **Тесты: unit на `enqueue_papers` с фейковым Redis + один интеграционный
   проход через живой Redis** (контейнер уже есть в окружении), без моков
   сигнатуры `eval`.

## Risks / Trade-offs

- [SADD прошёл, RPUSH упал → id навсегда в множестве, статья не проиндексируется] →
  известный потолок, задокументировать комментарием у кода; ручной ремонт
  `SREM paper_queue_ids <id>`; при появлении второго worker'а — MULTI/EXEC.
- [Старые payloads в живой очереди в «голом» формате без `url`] → `parse_payload`
  уже валидирует pydantic'ом; после дефолта `url` обе формы проходят. Worker
  перезапустить — старый процесс с чужим кодом не должен жить рядом с новым API.
- [Дефолт `url=""` маскирует ошибки клиентов, забывших url] → поле никем не
  читается; если начнёт читаться — включить валидацию тогда.

## Migration Plan

1. Правка `queuing.py` + `models.py`, тесты локально.
2. `docker compose restart worker api` (api — для чистоты, код он уже подхватил).
3. E2E-проверка: ingest без `url` → статус `queued` → worker лог `Indexed 1/1` → `embedded`.
4. Откат — `git revert`, рестарт контейнеров. Данные очереди совместимы в обе стороны.

## Open Questions

Нет. Латентность embedding'ов 30с не воспроизвелась при замерах (0.03–0.63s) —
